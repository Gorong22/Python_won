# 모바일 브라우저 이미지 로드/렌더링 크래시 원인 분석 보고서

## 📋 분석 개요

**문제 현상:**

- PC에서는 정상 동작하지만 모바일(Chrome/Safari)에서만 발생
- 피드/explore 페이지에서 이미지 다수 로드 시 화면 멈춤/튕김
- 검색 결과 이미지 빠른 표시 시 즉시 크래시
- 특정 스크롤 지점에서 이미지 깨짐/로딩 실패
- 외부 CDN URL(cafe24) 사용, PC에서는 정상

**분석 범위:**

- `index.html` (피드 페이지)
- `community.html` (커뮤니티 페이지)
- `mypage_reader.html` (마이페이지)
- `feed.js`, `community.js`, `mypage_reader.js`
- 관련 CSS 파일들

---

## 🔴 1. DOM 구조 및 동적 렌더링 문제

### 1.1 feed.js - 이미지 로드 중복 실행 위험

**위치:** `public/js/feed.js:4-30`

```javascript
window.addEventListener("DOMContentLoaded", () => {
  // ...
  setTimeout(() => {
    loadFeedImages();
  }, 100);
  // ...
});
```

**문제점:**

1. **중복 실행 방지 메커니즘 없음**: `loadFeedImages()`가 여러 번 호출될 수 있음
2. **이미지 중복 생성 가능성**: `loadFeedImages()` 내부에서 기존 이미지 제거 로직이 있으나(81-84줄), 빠른 연속 호출 시 race condition 발생 가능
3. **모바일에서 setTimeout 타이밍 불안정**: 모바일 브라우저의 이벤트 루프 지연으로 인해 100ms 지연이 불충분할 수 있음

**영향:**

- 모바일에서 DOM이 완전히 준비되기 전에 이미지 로드 시도
- 동일한 이미지가 여러 번 appendChild되어 메모리 누수
- 이미지 로드 콜백이 중복 실행되어 렌더링 충돌

---

### 1.2 community.js - innerHTML 전체 재생성

**위치:** `public/js/community.js:109-174`

```javascript
function renderPosts(filter = "전체") {
  postList.innerHTML = ""; // ⚠️ 전체 DOM 삭제

  // ... 필터링 로직 ...

  filteredPosts.forEach((post, index) => {
    postList.innerHTML += `...`; // ⚠️ 문자열 연결로 DOM 재생성
  });
}
```

**문제점:**

1. **innerHTML = ""로 전체 DOM 삭제**: 기존 이미지 요소들이 모두 제거되지만, 브라우저의 이미지 디코딩/메모리 해제가 즉시 이루어지지 않음
2. **문자열 연결로 DOM 재생성**: `innerHTML +=`는 매번 전체 HTML을 재파싱하고 재렌더링하여 대량의 reflow 발생
3. **이미지 로드 중단**: 필터링 시 기존 이미지 로드가 진행 중이어도 강제로 중단되어 메모리 누수
4. **모바일에서 메모리 압박**: 모바일 브라우저는 메모리 제한이 엄격하여 DOM 삭제 후 즉시 가비지 컬렉션이 이루어지지 않음

**영향:**

- 필터링 시마다 수십 개의 이미지가 한 번에 로드 중단 → 메모리 누수
- innerHTML 재생성으로 인한 대량 reflow → 모바일에서 프레임 드롭
- 이미지 디코딩 버퍼가 해제되지 않아 메모리 크래시

---

### 1.3 mypage_reader.js - 이미지 로드 타이밍 문제

**위치:** `public/js/mypage_reader.js:96-100`

```javascript
document.addEventListener("DOMContentLoaded", () => {
  setTimeout(() => {
    loadFeedItemImages();
    loadMyFeedImages();
  }, 100);
});
```

**문제점:**

1. **두 함수 동시 실행**: `loadFeedItemImages()`와 `loadMyFeedImages()`가 거의 동시에 실행되어 이미지 로드 경쟁 상태 발생
2. **이미지 중복 체크 불완전**: `if (item.querySelector("img"))` 체크가 있으나, 이미지가 로드 중일 때는 체크를 통과할 수 있음
3. **모바일 네트워크 병목**: 모바일에서 여러 이미지를 동시에 로드하면 네트워크 대역폭 부족으로 일부 이미지가 타임아웃

## 🔴 2. JavaScript 중복 실행 및 초기화 문제

### 2.1 DOMContentLoaded 중복 리스너

**발견 위치:**

- `feed.js:4` - `window.addEventListener("DOMContentLoaded", ...)`
- `feed.js:386` - `document.addEventListener("DOMContentLoaded", ...)`
- `community.js:192` - `document.addEventListener("DOMContentLoaded", ...)`
- `mypage_reader.js:96` - `document.addEventListener("DOMContentLoaded", ...)`
- `mypage_reader.js:179` - `document.addEventListener("DOMContentLoaded", ...)`

**문제점:**

1. **동일 파일 내 중복 리스너**: `feed.js`에서 DOMContentLoaded가 2번 등록됨
2. **전역 이벤트 위임과 충돌**: `document.addEventListener("click", ...)` 같은 전역 리스너가 이미지 로드와 동시에 실행되어 이벤트 루프 과부하
3. **모바일에서 이벤트 처리 지연**: 모바일 브라우저는 이벤트 루프가 느려서 중복 리스너가 누적되면 메인 스레드 블로킹

---

### 2.2 스크롤 이벤트 리스너 중복 등록

**위치:** `feed.js:163-169`, `feed.js:202-204`

```javascript
slider.addEventListener("scroll", () => {
  clearTimeout(scrollTimeout);
  scrollTimeout = setTimeout(() => {
    updateActiveDot();
  }, 50);
});

slider.addEventListener("scrollend", () => {
  updateActiveDot();
});
```

**문제점:**

1. **initSliderDotsSync() 중복 호출**: `loadFeedImages()`가 호출될 때마다 `initSliderDotsSync()`가 실행되어 동일한 슬라이더에 리스너가 중복 등록
2. **메모리 누수**: 이전 리스너가 제거되지 않아 스크롤 이벤트마다 여러 핸들러가 실행
3. **모바일 스크롤 성능 저하**: 모바일에서 스크롤 이벤트는 매우 빈번하게 발생하므로 중복 핸들러가 성능을 크게 저하시킴

---

### 2.3 이미지 로드 반복 루프

**위치:** `feed.js:50-118`

```javascript
function loadFeedImages() {
  const feedItemSections = document.querySelectorAll(".feed-item-section");

  feedItemSections.forEach((section, cardIndex) => {
    const placeholders = section.querySelectorAll(".content-placeholder");

    placeholders.forEach((placeholder, placeholderIndex) => {
      const existingImg = placeholder.querySelector("img");
      if (existingImg) {
        existingImg.remove(); // ⚠️ 기존 이미지 제거
      }

      const img = document.createElement("img");
      img.src = `${CDN_BASE}${fileName}`;
      placeholder.appendChild(img); // ⚠️ 즉시 appendChild
    });
  });
}
```

**문제점:**

1. **이미지 제거 후 즉시 재생성**: 기존 이미지의 메모리가 해제되기 전에 새 이미지를 생성하여 메모리 사용량 급증
2. **동기적 appendChild**: 이미지가 로드되기 전에 DOM에 추가되어 브라우저가 즉시 네트워크 요청 시작
3. **모바일 메모리 한계**: 모바일에서 수십 개의 이미지를 동시에 로드하면 메모리 한계 초과로 크래시

## 🔴 3. CSS Reflow 및 렌더링 문제

### 3.1 Grid 레이아웃의 대량 Reflow

**위치:** `public/css/community.css:188-193`

```css
.community-list {
  display: grid;
  grid-template-columns: repeat(2, 1fr);
  gap: 12px;
  padding-bottom: 120px;
}
```

**문제점:**

1. **innerHTML 재생성 시 전체 Grid 재계산**: `renderPosts()`에서 `innerHTML = ""` 후 재생성 시 모든 그리드 아이템의 위치를 재계산
2. **이미지 로드 시 레이아웃 시프트**: 이미지가 로드되면서 높이가 변경되어 그리드 레이아웃이 재계산됨
3. **모바일에서 Reflow 비용 증가**: 모바일 CPU가 약하여 대량 reflow 시 프레임 드롭 및 멈춤 현상

---

### 3.2 display:none → display:block 전환

**위치:** `feed.js:65`

```javascript
if (cardIndex >= 10) {
  section.style.display = "none"; // ⚠️ display 전환
  return;
}
```

**문제점:**

1. **스타일 변경으로 인한 Reflow**: `display: none`으로 변경 시 해당 요소와 하위 요소의 레이아웃이 재계산됨
2. **이미지 로드와 동시 발생**: 이미지 로드 중에 display 전환이 일어나면 렌더링 파이프라인 충돌

---

### 3.3 이미지 컨테이너 높이 불안정

**위치:** `public/css/feed.css:354-370`

```css
.content-placeholder {
  width: 100%;
  max-width: 402px;
  min-width: 100%;
  height: 505px; /* 고정 높이 */
  /* ... */
}

.content-placeholder img {
  width: 100%;
  height: 100%;
  object-fit: contain; /* ⚠️ contain 사용 */
}
```

**문제점:**

1. **object-fit: contain과 고정 높이 충돌**: 이미지 비율에 따라 실제 표시 영역이 달라져 레이아웃 시프트 발생 가능
2. **모바일에서 이미지 디코딩 지연**: 모바일에서 이미지 디코딩이 느려서 높이 계산이 지연되어 레이아웃이 깨짐

## 🔴 4. 이미지 로드 방식 문제

### 4.1 Lazy Loading 부재

**위치:** `feed.js:89`, `community.js:138`

```javascript
img.src = `${CDN_BASE}${fileName}`; // ⚠️ 즉시 src 설정
```

**문제점:**

1. **모든 이미지 즉시 로드**: 화면에 보이지 않는 이미지까지 모두 로드하여 메모리 사용량 급증
2. **네트워크 대역폭 고갈**: 모바일에서 수십 개의 이미지를 동시에 로드하면 네트워크가 포화되어 일부 이미지가 타임아웃
3. **HTML의 loading="lazy" 무효화**: JS로 동적 생성된 이미지는 HTML의 `loading="lazy"` 속성이 적용되지 않음

---

### 4.2 이미지 URL 프로토콜 누락

**위치:** `feed.js:37`, `community.js:47`, `mypage_reader.js:6`

```javascript
const CDN_BASE = "//ecimg.cafe24img.com/..."; // ⚠️ 프로토콜 상대 URL
```

**문제점:**

1. **모바일에서 프로토콜 해석 불안정**: 일부 모바일 브라우저에서 프로토콜 상대 URL이 예상과 다르게 해석될 수 있음
2. **HTTPS/HTTP 혼용 문제**: 페이지가 HTTPS인데 이미지가 HTTP로 로드되면 Mixed Content 경고 및 차단 가능

---

### 4.3 이미지 로드 에러 처리 불완전

**위치:** `feed.js:100-105`

```javascript
img.onerror = function () {
  console.error(`✗ Failed to load image: ${CDN_BASE}${fileName}`);
  this.style.display = "none"; // ⚠️ 단순히 숨김만 처리
};
```

**문제점:**

1. **에러 후 재시도 없음**: 네트워크 일시적 오류 시에도 재시도하지 않아 이미지가 영구적으로 깨짐
2. **메모리 해제 불확실**: `display: none`만으로는 이미지 메모리가 즉시 해제되지 않음
3. **모바일 네트워크 불안정**: 모바일에서 네트워크가 불안정할 때 이미지 로드 실패가 빈번하게 발생

## 🔴 5. 메모리 관리 문제

### 5.1 Node 생성/삭제 반복

**위치:** `feed.js:86-107`, `community.js:142-172`

**문제점:**

1. **이미지 요소 반복 생성**: 필터링이나 재렌더링 시마다 새로운 이미지 요소를 생성하지만 이전 요소의 메모리가 완전히 해제되지 않음
2. **이벤트 리스너 누수**: 이미지 요소에 직접 이벤트 리스너는 없으나, 부모 요소의 이벤트 위임으로 인해 참조가 유지될 수 있음
3. **모바일 가비지 컬렉션 지연**: 모바일 브라우저의 GC가 느려서 메모리가 누적되어 크래시 발생

---

### 5.2 innerHTML 사용으로 인한 메모리 누수

**위치:** `community.js:110`, `feed.js:223`

```javascript
postList.innerHTML = ""; // ⚠️ 전체 삭제
// ...
postList.innerHTML += `...`; // ⚠️ 문자열 연결
```

**문제점:**

1. **문자열 연결로 인한 메모리 복사**: `innerHTML +=`는 기존 HTML을 복사한 후 새 문자열을 연결하여 메모리 사용량이 2배로 증가
2. **DOM 파싱 오버헤드**: 매번 전체 HTML을 재파싱하여 CPU 사용량 급증
3. **모바일에서 메모리 압박**: 모바일의 제한된 메모리에서 대량의 문자열 복사가 크래시를 유발

## 📊 종합 분석 결과

### 주요 원인 우선순위

#### 🔴 **Critical (즉시 수정 필요)**

1. **community.js의 innerHTML 전체 재생성** (109-174줄)

   - 필터링 시마다 모든 이미지가 중단되고 재생성되어 메모리 누수 및 크래시
   - **영향도**: 매우 높음 (검색/필터링 시 즉시 크래시)

2. **feed.js의 이미지 로드 중복 실행** (4-30줄, 50-118줄)

   - 중복 실행 방지 메커니즘 없음
   - **영향도**: 높음 (피드 페이지 로드 시 튕김)

3. **스크롤 이벤트 리스너 중복 등록** (feed.js:123-212줄)
   - `initSliderDotsSync()`가 중복 호출되어 리스너 누적
   - **영향도**: 높음 (스크롤 시 성능 저하 및 메모리 누수)

#### 🟡 **High (우선 수정 권장)**

4. **Lazy Loading 부재**

   - 모든 이미지를 즉시 로드하여 메모리 사용량 급증
   - **영향도**: 중간-높음 (이미지가 많은 페이지에서 크래시)

5. **DOMContentLoaded 중복 리스너**

   - 동일 파일 내에서 여러 번 등록되어 초기화 중복 실행
   - **영향도**: 중간 (초기 로드 시 성능 저하)

6. **innerHTML 문자열 연결**
   - 메모리 복사 및 재파싱 오버헤드
   - **영향도**: 중간 (필터링 시 성능 저하)

#### 🟢 **Medium (개선 권장)**

7. **이미지 에러 처리 불완전**

   - 네트워크 오류 시 재시도 없음
   - **영향도**: 낮음-중간 (네트워크 불안정 시 이미지 깨짐)

8. **Grid 레이아웃 Reflow**
   - 이미지 로드 시 레이아웃 재계산
   - **영향도**: 낮음-중간 (스크롤 시 약간의 지연)

## 🎯 모바일에서만 발생하는 이유

1. **메모리 제한**: 모바일 브라우저는 메모리 제한이 엄격하여 대량의 이미지 로드 시 즉시 크래시
2. **CPU 성능**: 모바일 CPU가 약하여 대량 reflow 및 이미지 디코딩 시 메인 스레드 블로킹
3. **네트워크 불안정**: 모바일 네트워크가 불안정하여 이미지 로드 실패가 빈번하게 발생
4. **이벤트 루프 지연**: 모바일 브라우저의 이벤트 루프가 느려서 중복 실행이 누적되어 성능 저하
5. **가비지 컬렉션 지연**: 모바일 브라우저의 GC가 느려서 메모리 누수가 빠르게 누적
